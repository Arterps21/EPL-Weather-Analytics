# EPL Weather Analytics

**Веб-приложение для анализа футбольной статистики с учётом погодных условий.**

Проект создан в рамках курса «Безопасность высоконагруженных систем». Его задача состоит в том, чтобы на исторических данных английской Премьер-лиги сравнивать результативность команд в дождливую и сухую погоду.

## Что умеет приложение

Пользователь выбирает футбольный клуб и сезон, нажимает **«Провести анализ»** и получает сравнение двух групп матчей:

- количество матчей с дождём и без дождя;
- среднее количество забитых голов;
- средний показатель ожидаемых голов (xG).

Например, в сезоне **2017/18** у Liverpool в выборке 38 матчей: 7 с дождём и 31 без дождя. Среднее количество забитых голов составляет 1,29 и 2,42 соответственно.

Всего в проект загружены **4180 матчей** и погодные данные к ним. Анализ описывает статистические различия, но не доказывает, что погода стала их причиной. Машинное обучение не используется.

## Как это работает

Приложение построено на микросервисной архитектуре. Футбольные и погодные данные хранятся раздельно. После запроса пользователя система ставит аналитическое задание в очередь **RabbitMQ**. Отдельный обработчик получает необходимые данные, рассчитывает показатели и сохраняет результат в **Redis**. Веб-интерфейс показывает статус задания и готовую статистику.

Используются **Python / FastAPI, PostgreSQL, Redis, RabbitMQ, Nginx и Docker Compose**. Система состоит из девяти контейнеров. Между компонентами настроено разделение Docker-сетей: сервисы имеют доступ только к необходимым им сетевым сегментам.

## Как посмотреть

Веб-интерфейс после запуска проекта доступен по адресу:

**http://localhost:3000**

Для запуска на компьютере с Docker Desktop из корня проекта:

```powershell
docker compose up -d --build
```

Для первого запуска в новом окружении также необходимы файл `.env` с учётными данными и первоначальный импорт данных из `epl_weather_matches.csv` в две PostgreSQL. В подготовленном демонстрационном окружении данные уже загружены.

## Состояние учебного проекта

- **Этап 1.** Выбор и описание проекта: выполнен.
- **Этап 2.** Микросервисы, веб-интерфейс и контейнеризация: выполнен.
- **Этап 3.** Работа с PostgreSQL, Redis и RabbitMQ: реализованы основные сценарии; этап выполнен частично, операции `UPDATE` и `DELETE` пока не добавлены.
- **Этап 4.** Сегментация сетей: реализована; демонстрировались разрешённые и запрещённые соединения и ошибка при разрыве необходимой связи.
- **Этап 5.** Отказоустойчивость, репликация и резервное копирование: отложены до итоговой защиты.
